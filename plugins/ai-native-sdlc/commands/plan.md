---
description: Write an implementation plan from an accepted spec, before any code
---

Use the `implementation-plan` skill for: $ARGUMENTS

Start in plan mode. Read the spec and the code it touches, then produce a
plan naming the files that change, the order of work, the risks, the
options you rejected, and the tests that prove it.

Then interrogate your own plan: what could this break, which step is
riskiest, what did you choose not to do. Do not write code until I accept
the plan.
